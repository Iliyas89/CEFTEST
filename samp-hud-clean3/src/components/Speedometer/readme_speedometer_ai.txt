ТЕХНИЧЕСКОЕ ЗАДАНИЕ: ИНТЕГРАЦИЯ CEF-СПИДОМЕТРА В ИГРУ (PAWN + КЛИЕНТСКИЙ СКРИПТ)
================================================================================

ОБЩЕЕ ОПИСАНИЕ СИСТЕМЫ:
Мы интегрируем кастомный интерфейс спидометра, написанный на React (CEF). 
Сайт спидометра расположен на внешнем веб-хостинге. Взаимодействие между игрой 
и веб-интерфейсом происходит через единую глобальную функцию в браузере:
👉 window.updateSpeedometer(dataJsonString);

Функция принимает строго ОДИН аргумент — строку в формате JSON, которая 
содержит текущие состояния автомобиля.

================================================================================
ЧАСТЬ 1: АРХИТЕКТУРА ДАННЫХ И ФОРМАТ JSON
================================================================================
Интерфейс ожидает JSON-объект со следующими ключами (все ключи необязательны, 
можно присылать только изменившиеся параметры):

{
  "speed": 0,       // [Число] Текущая скорость автомобиля (в км/ч)
  "fuel": 80,       // [Число] Процент бензина в баке (0 - 100)
  "mileage": 1245,  // [Число] Общий пробег автомобиля (одометр)
  "hp": 100,        // [Число] Здоровье автомобиля в процентах (0 - 100)
  "engine": true,   // [Булево] Статус двигателя (true - заведен / false - заглушен)
  "lights": false,  // [Булево] Статус фар (true - включены / false - выключены)
  "parking": false, // [Булево] Ручной тормоз (true - затянут / false - снят)
  "locked": false,  // [Булево] Замок дверей (true - закрыт / false - открыт)
  "turnLeft": false,// [Булево] Левый поворотник (true - горит / false - потух)
  "turnRight":false // [Булево] Правый поворотник (true - горит / false - потух)
}

================================================================================
ЧАСТЬ 2: ОБЯЗАННОСТИ КЛИЕНТСКОЙ ЧАСТИ (ИГРА / ЛАУНЧЕР) — ОПТИМИЗАЦИЯ НАГРУЗКИ
================================================================================
ПРАВИЛО ОПТИМИЗАЦИИ: Чтобы избежать лагов на сервере при онлайне в 1000+ игроков,
высокочастотные данные берутся НАПРЯМУЮ ИЗ ПАМЯТИ ИГРЫ на стороне клиента!

Что должен делать клиентский скрипт лаунчера (C++ / C# / JS плагин):
1. Инициализация:
   При посадке игрока на место водителя (seat == -1), создать CEF-браузер поверх 
   игры и загрузить URL нашего спидометра с хостинга. При выходе из авто — уничтожить браузер.
   
2. Клиентский Таймер (Высокая частота — каждые 50-100 мс):
   Локально считывать из памяти запущенной GTA SA следующие параметры:
   - СКОРОСТЬ: Взять векторную скорость авто, перевести в км/ч (умножить на 3.6).
   - ХП МАШИНЫ: Взять текущее здоровье авто (в игре от 0.0 до 1000.0) и перевести в проценты (разделить на 10).
   Сформировать JSON и мгновенно «выстрелить» в CEF через execute:
   `window.updateSpeedometer('{"speed": ' + speed + ', "hp": ' + hp + '}');`

3. Обработка входящих RPC-пакетов от сервера:
   Клиент должен слушать события от сервера (Бензин, Двигатель, Фары, Замок) 
   и сразу же пересылать их в CEF-браузер через тот же window.updateSpeedometer.

================================================================================
ЧАСТЬ 3: ОБЯЗАННОСТИ СЕРВЕРНОЙ ЧАСТИ (PAWN) — ПАКЕТНАЯ ЛОГИКА
================================================================================
Сервер обрабатывает только системные данные. Сервер НЕ ДОЛЖЕН гонять скорость 
или ХП машины через сетевые пакеты! Сервер отправляет пакет только в момент изменения состояния.

Что нужно реализовать в Pawn:

1. Переменные в enum транспорта:
   Обеспечить хранение данных в массиве транспорта (например, VehicleInfo[vehicleid]):
   - vFuel (Бензин автомобиля)
   - vMileage (Пробег автомобиля)
   - vLocked (Статус замка дверей: 0 - открыт, 1 - закрыт)

2. Таймер расхода топлива (Низкая частота — например, раз в 10-20 секунд):
   Если у автомобиля заведен двигатель (`engine == true`), уменьшать значение `vFuel` 
   в зависимости от типа транспорта. При уменьшении бензина — отправить пакет 
   ОДНОМУ конкретному игроку (водителю), чтобы обновить шкалу.

3. Переключение состояний (Команды / Кнопки):
   - При вводе команды /engine или нажатии кнопки завода: изменить системный статус двигателя 
     и отправить пакет водителю: `{"engine": true/false}`.
   - При вводе команды /lock или нажатии кнопки закрытия: изменить `vLocked` 
     и отправить пакет водителю: `{"locked": true/false}`.
   - Аналогично для фар, ручника и поворотников. При нажатии клавиши — сервер переключает 
     состояние и уведомляет клиент водителя ОДНИМ пакетом.

4. Синхронизация при посадке:
   Как только игрок садится в машину на место водителя, сервер обязан отправить ему 
   стартовый пакет со всеми текущими параметрами машины из базы данных (Бензин, Пробег, Замок).

================================================================================
ИНСТРУКЦИЯ ДЛЯ ИИ-РАЗРАБОТЧИКА:
1. Не используй высокочастотные серверные таймеры для обновления скорости!
2. Напиши чистый код создания CEF-окна на клиенте и локального считывания скорости/хп.
3. Напиши Pawn-команды для взаимодействия с переменными бензина, замка и отправки RPC-событий.
